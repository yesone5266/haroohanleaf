# 규칙 (Rules)

## 기본 원칙
- HTML, TypeScript, CSS만 사용하여 프론트엔드를 개발한다.
- 사용자의 요구사항을 충분히 이해한 후 구현한다.
- 요구사항이 불명확한 경우 추측하지 말고 질문한다.
- 기존 기능을 유지하면서 필요한 부분만 수정한다.
- 코드의 가독성과 유지보수성을 최우선으로 한다.
- 동일한 기능을 중복 구현하지 않는다(DRY 원칙).
- 불필요한 라이브러리나 복잡한 구현은 사용하지 않는다.

## 코드 스타일

### 공통
- 의미 있는 변수명, 함수명, 클래스명을 사용한다.
- 축약어 사용을 최소화한다.
- 상수는 UPPER_SNAKE_CASE를 사용한다.
- 함수 하나는 하나의 역할만 수행하도록 작성한다.
- 매직 넘버를 사용하지 말고 상수로 분리한다.
- 적절한 들여쓰기와 공백을 유지한다.
- 사용하지 않는 변수, 함수, import는 제거한다.
- 불필요한 주석은 작성하지 않는다.
- 복잡한 로직에는 의도를 설명하는 주석만 작성한다.

### TypeScript
- any 타입 사용을 지양한다.
- 가능한 모든 값에 적절한 타입을 지정한다.
- interface를 우선 사용하며 필요 시 type을 사용한다.
- const를 기본으로 사용하고 필요한 경우에만 let을 사용한다.
- var는 사용하지 않는다.
- 화살표 함수(Arrow Function)를 기본으로 사용한다.
- Optional Chaining(?.), Nullish Coalescing(??) 등을 적극 활용한다.
- Promise보다는 async/await를 우선 사용한다.
- 긴 함수는 작은 함수로 분리한다.
- DOM 요소는 가능한 명확한 타입으로 선언한다.

### HTML
- 시맨틱 태그를 우선 사용한다.
- 불필요한 div 사용을 최소화한다.
- 접근성을 고려하여 alt, label, aria 속성을 적절히 사용한다.
- id는 꼭 필요한 경우에만 사용한다.
- 반복되는 요소는 일관된 구조를 유지한다.

### CSS
- 클래스 기반 선택자를 우선 사용한다.
- id 선택자는 최소한으로 사용한다.
- !important 사용을 지양한다.
- 색상, 폰트 크기, 간격 등은 CSS 변수(--variable)로 관리한다.
- Flexbox와 Grid를 상황에 맞게 사용한다.
- 중복 스타일을 최소화한다.
- 클래스명은 역할 중심으로 작성한다.
- 애니메이션은 필요한 경우에만 적용한다.
