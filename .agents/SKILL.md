## 목적
변경 사항을 분석하여 의미 있는 단위로 Git 커밋을 생성한다.

## 수행 절차

1. 변경된 파일을 확인한다.
2. 변경 내용을 분석한다.
3. 관련된 변경 사항끼리 하나의 커밋으로 묶는다.
4. 서로 다른 기능은 별도의 커밋으로 분리한다.
5. 커밋 메시지를 작성한다.
6. 커밋을 생성한다.

## 커밋 규칙

- 하나의 커밋은 하나의 목적만 가진다.
- 기능 추가와 버그 수정은 같은 커밋에 포함하지 않는다.
- 리팩토링은 별도의 커밋으로 분리한다.
- 의미 없는 커밋을 생성하지 않는다.
- 불필요한 파일은 커밋하지 않는다.

## 커밋 메시지 규칙

형식

<emoji> <type>: <한글 요약>

예시

✨ feat: 식물 성장 애니메이션 추가
🐛 fix: 인벤토리 불러오기 오류 수정
♻️ refactor: 펫 상태 관리 로직 개선
🎨 style: 버튼 간격 및 색상 정리
📝 docs: README 설치 방법 수정
✅ test: 체크리스트 기능 테스트 추가
🔧 chore: TypeScript 설정 파일 수정

## Commit Type

✨ feat
- 새로운 기능 추가

🐛 fix
- 버그 수정

♻️ refactor
- 기능 변경 없이 코드 구조 개선

🎨 style
- 코드 스타일, CSS, 포맷팅 수정

📝 docs
- 문서 수정

✅ test
- 테스트 추가 및 수정

🔧 chore
- 빌드, 설정, 패키지 등 기타 작업

## 추가 규칙

- Summary(요약)는 한글로 작성한다.
- 현재 시제의 자연스러운 표현을 사용한다.
- 핵심 변경 사항만 간결하게 작성한다.
- 마침표를 붙이지 않는다.
- 가능한 50자 이내로 작성한다.
- 여러 변경 사항이 있다면 대표 변경 사항을 기준으로 작성한다.
